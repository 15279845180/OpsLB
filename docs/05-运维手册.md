# OpsLB 运维手册（V2.5）

## 一、日常巡检

### 1.1 服务状态检查

```bash
# Go 后端
systemctl status opslb

# OpenSIPS
systemctl status opensips

# Redis
systemctl status redis
redis-cli ping

# MySQL
systemctl status mysqld
```

### 1.2 端口监听确认

```bash
ss -tlnp | grep -E "5060|8080|6379|3306"
# 预期输出：
# 5060  OpenSIPS (SIP)
# 8080  OpsLB    (Go API)
# 6379  Redis
# 3306  MySQL
```

### 1.3 并发状态查看

```bash
# 查看所有入局网关并发
redis-cli KEYS "inbound:*:calls" | while read key; do
    echo "$key: $(redis-cli GET $key)"
done

# 查看所有出局网关并发
redis-cli KEYS "gateway:*:calls" | while read key; do
    echo "$key: $(redis-cli GET $key)"
done

# 查看当前活跃通话数
redis-cli KEYS "call_alloc:*" | wc -l
```

### 1.4 话单表检查

```sql
-- 查看今日话单量
SELECT COUNT(*) FROM cdr_call_20260511;

-- 查看今日接通率
SELECT 
    COUNT(*) AS total,
    SUM(CASE WHEN status_code = 200 THEN 1 ELSE 0 END) AS answered,
    ROUND(SUM(CASE WHEN status_code = 200 THEN 1 ELSE 0 END) / COUNT(*) * 100, 2) AS rate
FROM cdr_call_20260511;

-- 查看失败原因分布
SELECT status_code, status_text, COUNT(*) AS cnt
FROM cdr_call_20260511
WHERE status_code >= 400
GROUP BY status_code, status_text
ORDER BY cnt DESC
LIMIT 10;
```

## 二、性能压测

### 2.1 SIPp 安装

```bash
yum install -y sipp
# 或 apt install -y sipp
```

### 2.2 基础压测场景

```bash
# 场景1：100 CPS 持续呼叫
sipp -sf uac.xml 192.168.1.168:5060 \
    -r 100 -rp 1000 -m 10000 \
    -trace_err -trace_msg

# 场景2：500 CPS 高并发
sipp -sf uac.xml 192.168.1.168:5060 \
    -r 500 -rp 5000 -m 50000

# 场景3：BYE 释放测试
sipp -sf uac_bye.xml 192.168.1.168:5060 \
    -r 50 -m 1000

# 参数说明：
# -r 100    : 每秒发起100个呼叫 (CPS)
# -rp 1000  : 速率计算周期1秒
# -m 10000  : 总共发起10000个呼叫
```

### 2.3 压测期间监控

```bash
# Go 进程 CPU/内存
top -p $(pgrep OpsLB)

# Redis 延迟（持续监控）
watch -n 1 'redis-cli --latency-history'

# OpenSIPS 实时日志
tail -f /var/log/messages | grep -E "ALLOCATE|RELEASE|ERROR"

# 网络连接数
watch -n 1 'ss -tan | grep -E "5060|8080|6379" | wc -l'
```

### 2.4 压测指标参考

| CPS | allocate P99 | Redis P99 | 预期状态 |
|-----|-------------|-----------|---------|
| 100 | < 3ms | < 1ms | 正常 |
| 500 | < 5ms | < 2ms | 正常 |
| 1000 | < 10ms | < 3ms | 需监控 |
| 2000+ | < 20ms | < 5ms | 需优化 |

## 三、故障排查

### 3.1 OpenSIPS 相关

**问题：INVITE 进来后被 drop**

```bash
# 1. 检查 IP 是否在白名单
mysql> SELECT * FROM cfg_inbound_ips WHERE ip = '源IP';

# 2. 检查 permissions 模块状态
opensipsctl fifo address_dump

# 3. 查看 OpenSIPS 日志（log_level=3 会打印 drop 日志）
tail -f /var/log/messages | grep "Not in whitelist"
```

**问题：allocate 返回空响应**

```bash
# 1. 检查 Go 服务是否正常运行
curl http://127.0.0.1:8080/api/login

# 2. 手动测试 allocate 接口
curl -X POST http://127.0.0.1:8080/api/call/allocate \
  -H "Content-Type: application/json" \
  -d '{"call_id":"test123","caller":"13800138000","called":"13900139000","inbound_ip":"10.0.0.1"}'

# 3. 检查 connection_timeout 是否过小
grep connection_timeout /etc/opensips/opensips.cfg
# 建议值：1秒（最小安全值）
```

### 3.2 Redis 相关

**问题：并发计数器异常（负数或不对）**

```bash
# 查看具体网关计数
redis-cli GET gateway:3:calls
redis-cli GET inbound:1:calls

# 手动修正（谨慎操作）
redis-cli SET gateway:3:calls 0
redis-cli DEL gateway:3:calls
```

**问题：Redis 内存过高**

```bash
# 查看内存使用
redis-cli INFO memory | grep used_memory_human

# 查看 key 数量
redis-cli DBSIZE

# 清理过期 key（通常会自动过期，无需手动操作）
redis-cli --scan --pattern "gateway:*:cps:*" | xargs redis-cli DEL
```

### 3.3 话单相关

**问题：话单表不存在**

```bash
# 手动创建当天表
mysql opslb -e "CREATE TABLE IF NOT EXISTS cdr_call_$(date +%Y%m%d) LIKE cdr_call_template"

# 如果没有模板表，重启Go服务（启动时会自动创建）
systemctl restart opslb
```

**问题：话单丢失**

```bash
# 1. 检查异步队列是否满
tail -f /path/to/opslb.log | grep "Queue full"

# 2. 检查批量写入错误
tail -f /path/to/opslb.log | grep "Batch insert failed"

# 3. 增加队列容量（修改 cache/callrecord.go 中的 callRecordQueueSize）
```

### 3.4 HTTP 端口耗尽

**症状：** OpenSIPS 日志大量 `connection refused` 或 `timeout`

**排查：**

```bash
# 查看 TIME_WAIT 连接数
ss -tan | grep TIME_WAIT | wc -l

# 查看 ephemeral 端口范围
cat /proc/sys/net/ipv4/ip_local_port_range

# 临时优化（重启后失效）
echo "1024 65535" > /proc/sys/net/ipv4/ip_local_port_range
echo 1 > /proc/sys/net/ipv4/tcp_tw_reuse
```

**根本解决：** V2.5 已将 INVITE 路径从 3次 HTTP 降到 1次，大幅降低连接数。

## 四、日常维护

### 4.1 日志清理

```bash
# Go 日志轮转（建议配置 logrotate）
cat > /etc/logrotate.d/opslb << 'EOF'
/var/log/opslb/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}
EOF
```

### 4.2 话单归档

```sql
-- 每月归档上月话单表
-- 方式1：导出后删除
SELECT CONCAT('DROP TABLE IF EXISTS ', TABLE_NAME, ';')
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'opslb'
  AND TABLE_NAME LIKE 'cdr_call_%'
  AND TABLE_NAME < CONCAT('cdr_call_', DATE_FORMAT(CURDATE(), '%Y%m'));

-- 方式2：保持7天数据，自动清理脚本
```

### 4.3 Redis 监控

```bash
# 慢查询检查
redis-cli SLOWLOG GET 10

# 连接数检查
redis-cli INFO clients | grep connected_clients

# 命中率检查
redis-cli INFO stats | grep keyspace
```

## 五、告警阈值建议

| 指标 | 告警阈值 | 严重阈值 |
|------|---------|---------|
| Go 进程 CPU | > 80% | > 95% |
| Go 进程 内存 | > 1GB | > 1.5GB |
| allocate 延迟 P99 | > 20ms | > 50ms |
| Redis 连接数 | > 200 | > 400 |
| 话单队列积压 | > 5000 | > 8000 |
| TIME_WAIT 连接 | > 30000 | > 50000 |
| 呼叫失败率 | > 5% | > 10% |

## 六、快速恢复

### 6.1 Go 服务重启

```bash
systemctl restart opslb
# 注意：重启会导致内存网关缓存重建，需要30秒预热
```

### 6.2 OpenSIPS 重启

```bash
systemctl restart opensips
# 注意：重启会导致所有正在进行的通话中断
# 推荐使用 opensipsctl fifo 做优雅操作
```

### 6.3 全链路重启顺序

```bash
# 1. 先重启 Redis（快速恢复）
systemctl restart redis

# 2. 重启 Go（等待 Redis 就绪）
systemctl restart opslb
sleep 2

# 3. 最后重启 OpenSIPS
systemctl restart opensips
```
