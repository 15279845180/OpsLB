# OpsLB 开发规范（Go 后端）

## 一、项目结构约定

```
handlers/     ← HTTP 请求处理（Controller 层）
cache/        ← Redis + 内存缓存（Service 层）
models/       ← 数据模型（Model 层）
router/       ← 路由注册
middleware/   ← JWT 中间件
config/       ← 配置加载
database/     ← MySQL 连接
```

**分层原则：**
- `handlers/` 只做请求解析、参数校验、调用 cache 层、返回响应
- `cache/` 封装所有 Redis 操作 + 内存缓存逻辑
- `models/` 纯数据结构定义，不包含业务逻辑

## 二、命名规范

### 2.1 函数命名

```go
// ✅ 正确：动词开头，清晰表达意图
func AllocateInboundCall(callID string, ...) (string, int64, error)
func GetOutboundGateways(c *gin.Context)
func filterAvailableGatewaysFromCache(gateways []*OutboundGatewayInfo) ...

// ❌ 错误：含糊不清
func DoAllocate(...)
func Process(...)
```

### 2.2 变量命名

```go
// ✅ 正确
inboundGW, exists := cache.GetInboundGatewayByIP(req.InboundIP)
priorityGroups, priorities := cache.GetOutboundGateways()

// ❌ 错误
gw, ok := ...
data, list := ...
```

### 2.3 日志前缀

每个模块使用统一前缀：
```go
log.Printf("[ALLOCATE] ...")     // call.go
log.Printf("[RELEASE] ...")      // call.go
log.Printf("[EVENT-bye] ...")    // outbound.go
log.Printf("[GATEWAY-CACHE] ...")// gateway.go
log.Printf("[CALL-RECORD-QUEUE] ...") // callrecord.go
```

## 三、错误处理

### 3.1 Redis 错误

```go
result, err := Redis.Eval(...).Result()
if err != nil {
    log.Printf("[ALLOCATE] Redis error: %v, call_id=%s", err, callID)
    c.JSON(http.StatusInternalServerError, gin.H{"error": "redis error"})
    return
}
```

### 3.2 数据库错误

```go
if err := database.DB.Create(&record).Error; err != nil {
    log.Printf("[DB] Insert failed: %v, call_id=%s", err, callID)
    // 不阻塞主流程
}
```

### 3.3 回滚策略

分配失败时必须回滚已分配资源：
```go
// 入局已分配，选路失败 → 必须回滚
if selected == nil {
    cache.ReleaseCall(req.CallID)  // 回滚入局并发
    return error
}
```

## 四、并发安全

### 4.1 Redis Lua 原子操作

所有涉及多步 Redis 操作的逻辑必须使用 Lua 脚本：
```go
luaScript := `
    local key = KEYS[1]
    local current = redis.call('HGET', key, 'status')
    if current == 'released' then
        return 'REJECT'
    end
    ...
`
```

### 4.2 内存缓存读写锁

```go
gatewayCache.mu.RLock()   // 读锁
defer gatewayCache.mu.RUnlock()

gatewayCache.mu.Lock()    // 写锁（刷新时）
defer gatewayCache.mu.Unlock()
```

## 五、性能规范

### 5.1 避免阻塞 SIP 信令

```go
// ✅ 正确：异步操作不阻塞主流程
go updateCallRecordAsync(callID, reason, statusCode)
cache.EnqueueCallRecord(record)  // 非阻塞入队

// ❌ 错误：同步操作阻塞响应
database.DB.Create(&record)  // 高并发下会阻塞
```

### 5.2 Channel 非阻塞写入

```go
select {
case CallRecordQueue <- record:
    // 成功
default:
    log.Printf("Queue full, dropping record: %s", record.CallID)
    // 丢弃也不阻塞
}
```

### 5.3 批量写入

话单写入使用批量模式：100条/批 或 500ms 超时强制写入。

## 六、API 设计规范

### 6.1 OpenSIPS 内部接口（无需 JWT）

```go
// router.go 中直接注册，不加中间件
call := r.Group("/api/call")
{
    call.POST("/allocate", handlers.Allocate)
    call.POST("/release", handlers.ReleaseCall)
}
```

### 6.2 管理接口（需要 JWT）

```go
authorized := r.Group("/api")
authorized.Use(middleware.AuthMiddleware(cfg.JWT.Secret))
```

### 6.3 响应格式

```go
// 成功
c.JSON(http.StatusOK, AllocateResponse{Allowed: true, ...})

// 业务拒绝（非HTTP错误码）
c.JSON(http.StatusOK, AllocateResponse{Allowed: false, ErrorCode: -3, Reason: "..."})

// 系统错误
c.JSON(http.StatusInternalServerError, gin.H{"error": "redis error"})
```

## 七、测试规范
